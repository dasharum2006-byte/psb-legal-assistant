# Решение: оставляем два чанкера (замер, не вкусовщина)

Вопрос: объединить нарезку сабмита и бэкенда в одну реализацию?

Замер (18 демо-вопросов, живая модель `deepseek-v4.1-flash`, судья локальный
`scripts/ab_variants.py` — два прогона на вопрос со сменой A/B, чтобы убрать
позиционное смещение).

## Чанкеры

| | сабмит | бэкенд |
|---|---|---|
| чанков | 324 | 875 |
| медиана текста | 968 символов | 214 символов |
| лимит статьи | 1500 | 1800 |

## Сторона сабмита (70% оценки)

A = чанкер сабмита, B = чанкер бэкенда, конвейер сабмита одинаковый.

```
A: 13 побед, B: 2 победы, ничьих 3 из 18   → A лучше (72% / 11% / 17%)
```

Причина: у сабмита есть реранкер, соседи и второй проход. Они выигрывают,
когда чанк — целый пункт со всеми оговорками. Дробление на 200-символьные
куски этот конвейер только размывает.

**Решение: сабмит остаётся на своём чанкере.**

## Сторона бэкенда (30%, ручная оценка демо)

A = текущий чанкер бэкенда, B = чанкер сабмита (индекс `data/index_submit_chunks`).

```
A: 7 побед, B: 7 побед, ничьих 4 из 18   → паритет
```

Плюс метрики против эталона: сходство 23.9% (текущий) против 20.0% (чанкер
сабмита), покрытие чисел 8/15 против 7/15 — то есть выигрыша от переноса нет.

**Решение: бэкенд остаётся на своём чанкере.**

## Почему это не дублирование

Разные конвейеры — разные требования к гранулярности. Общее вынесено в
`backend/app/` и генерируется в сабмит (`scripts/sync_submit.py`):

- `app/rag/parser.py` — чтение базы (TXT/MD/DOCX), метаданные;
- `app/rag/textsel.py` — выбор предложения («сумма первой»);
- `app/llm/prompt.py` — `SYSTEM_PROMPT`.

Дрейф этих блоков ловит `backend/tests/test_prompt_sync.py`.

## Как перезамерить

```bash
python scripts/run_variant.py --chunker backend     # сабмит с чужим чанкером
INDEX_DIR=data/index_submit_chunks python scripts/eval_backend.py out.csv
python scripts/ab_variants.py файл_A.csv файл_B.csv
```
